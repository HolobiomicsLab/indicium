    Figure ¶

    Bases: ConfiguredBaseModel

    A figure, table, or other display item from a scholarly publication. Carries optional FaBiO sub-type classification (via figure_type) and provenance (source_doi). Linked from Evidence.of_figure when the evidence is grounded in a visual artefact rather than a text passage.

    FigureType ¶

    Bases: str, Enum

    FaBiO-aligned classification of figure and display item types found in scholarly publications. Values map to FaBiO sub-classes of fabio:Figure and fabio:Table.

    Script ¶

    Bases: ConfiguredBaseModel

    A code artefact (script, notebook, or pipeline) from a scholarly publication. Carries role classification (script_type), programming language, repository URL, and optional pinned commit. Linked from Evidence.of_script when the evidence is grounded in code rather than a text passage or figure.

    ScriptType ¶

    Bases: str, Enum

    Role-based classification of code artefacts in scholarly publications. All values map to fabio:ComputerProgram; the enum value itself conveys the functional role within the paper's methodology.

    DataAsset ¶

    Bases: ConfiguredBaseModel

    A data artefact (dataset, supplementary file, or public repository deposit) from a scholarly publication. Carries content-type classification (dataset_type), file format, accession number, and hosting repository. Linked from Evidence.of_dataset when the evidence is grounded in data rather than a text passage.

    DatasetType ¶

    Bases: str, Enum

    Content-type classification of data artefacts in scholarly publications. Values map to dcat:Dataset; the enum value conveys the domain/format category of the data.

    ClaimLink ¶

    Bases: ConfiguredBaseModel

    A typed semantic link between two Claims using CiTO predicates. Enables contradiction detection, argument graphs, and claim ledger navigation.

    Vocabulary bases (indicium.iri_bindings)¶

    Import these instead of spelling the IRIs; see the URI scheme.

    indicium.iri_bindings ¶

    Verified ontology IRIs for the indicium vocabularies.

    Provenance: seeded from ASB semantic.py, then verified against EBI OLS4 / CiTO (plan Task 2). Update here AND in the LinkML schema meaning: together.

    Verification method¶

    ECO labels were fetched from: https://www.ebi.ac.uk/ols4/api/ontologies/eco/terms?iri=http://purl.obolibrary.org/obo/ECO_ CiTO predicates were confirmed to resolve (HTTP 302 → 200) at: http://purl.org/spar/cito/

    Changes vs. ASB semantic.py¶

    • citation: ECO:0000305 → ECO:0000033 Old label: "curator inference used in manual assertion" (wrong branch — this is under inferential/curator-inference, not literature citation). New label: "author statement supported by traceable reference" — an author assertion whose support can be traced to a cited reference; this is the standard GO/ECO code for evidence derived from a published source.

    • inference: ECO:0000001 → ECO:0000361 Old label: "inference from background scientific knowledge" — a leaf under ECO:0000205 (curator inference) → ECO:0000361. It is too specific (curator only) and was incorrectly described in the task spec as the root. New label: "inferential evidence" — the direct child of ECO:0000000 (root "evidence") that heads the entire inference/reasoning branch. Using the upper-level branch term is correct for a vocabulary binding that must subsume all forms of computational, logical, and manual inference.

    • speculation: ECO:0007672 → ECO:0000034 Old label: "computational evidence" — entirely wrong; this is about computer-generated data, not hypothetical assertions. New label: "author statement without traceable support" — an assertion not associated with results presented or a cited reference. This is the closest available ECO upper-level term for a speculative/hypothetical claim. ECO does not have a dedicated "speculation" class; this is the best match.

    All other terms (data, knowledge) are retained with confirmed labels.

    Quote verification (indicium.verify)¶

    indicium.verify ¶

    Quote verification kernel — match an LLM-extracted quote against source text.

    Pure-Python, dependency-light, never raises. Shared across projects that ground claims / parameters / failure-modes in source passages (Perspicacité, ASB).

    Additive to the indicium standard: this module adds a verifier verb alongside the existing data model (Evidence.quote_exact / TextQuoteSelector). It does NOT touch generated/model.py, the SHACL shapes, or any enum.

    VerificationResult also carries a char_span — (start, end) offsets into the matched candidate's original (un-normalized) text — so callers can highlight or re-slice the exact source region instead of re-searching for it.

    verify_quote(..., punctuation_flexible=True) adds an opt-in pass that matches a quote's alphanumeric tokens in order across arbitrary punctuation/whitespace (e.g. "P=0.001" ~ "P = 0.001,"), so a verbatim-modulo-punctuation quote verifies instead of degrading to a sub-threshold LCS. This mirrors ASB claim_ledger's token-sequence matcher, letting both projects share one kernel.

    Functions¶

    verify_quote(quote: str, candidates: Sequence[str], *, near_threshold: float = 0.9, punctuation_flexible: bool = False) -> VerificationResult ¶

    Verify quote against candidates (source passage texts).

    Outcomes
    • verified: quote is contained in some candidate (whitespace-flexible, case-sensitive). quote_exact = the candidate's verbatim span; score = 1.0; char_span = (start, end) offsets into that candidate's original text.
    • repaired: no containment, but the longest common substring vs the best candidate clears near_threshold (ratio over len(normalized quote)). quote_exact = that LCS region from the candidate; score = ratio; char_span best-effort (the normalized span is re-located in the original candidate; may be None).
    • unverified: nothing clears the threshold (likely paraphrase/hallucination). matched_index = quote_exact = char_span = None; score = best below-threshold ratio (0.0 when quote/candidates are empty or share no run).

    With punctuation_flexible=True, an opt-in pass between containment and LCS matches the quote's alphanumeric tokens in order across arbitrary punctuation (e.g. "P=0.001" ~ "P = 0.001,"); a hit is verified, score 1.0. Off by default so existing thresholds are unchanged.

    Never raises: empty/whitespace quote or empty candidates -> unverified. Ties resolved by highest score, then lowest index.

    ASTRA bridge (indicium.astra_bridge)¶

    Typed conversion between Claim objects and ASTRA insights. Needs the astra extra.

    indicium.astra_bridge ¶

    ASTRA ↔ Indicium bridge — convert between ASTRA Insight dicts and Indicium Claims.

    Optional-extra-gated: pyyaml must be installed (pip install "indicium-standard[astra]" or pip install pyyaml). The pyyaml extra is already in the codegen extra and dev dependency-group, so it is always available during development.

    Gap 6 implementation from the Indicium v1.3 design spec.

    insight_to_claim(insight: dict, *, analysis_id: str, source_doi: str | None = None) -> 'Claim' ¶

    Convert an ASTRA Insight dict to a best-effort Indicium Claim.

    Mapping rules: - subject/object: split claim text at verb heuristic, or use full text as object. - qualifier: defaults to has_property; overridden when a known verb is found. - relation: same as qualifier_str (the matched verb phrase) or "has_property". - context: ASTRA scope field joined with tags; empty string if absent. - asserted_by: set to analysis_id. - astra_insight_ref: set to "{analysis_id}/{insight['id']}".

    		 required

    		 None

    ASTRA, dict-based (indicium.adapters.astra, deprecated)¶

    indicium.adapters.astra ¶

    Project an indicium Claim onto an ASTRA Insight (lossy — claim becomes a string).

    ASTRA Insight = {id, claim (str), evidence: [{doi|artifact, quote:{exact}}]}. The 5-slot SuperPattern is flattened into the claim string; full typing is preserved in the RDF/RO-Crate forms, not here.

    ASB task card adapter (indicium.adapters.scitask)¶

    indicium.adapters.scitask ¶

    Project an indicium Claim onto the EvidenceSnippet dict of an ASB task card.

    The target structure is the EvidenceSnippet class of the ASB task card schema, asb_schema/asb_card.yaml in the asb-schema package (asb-schema>=0.4.0). Its fields are snippet_id, source_path, reason and text. The module keeps its earlier name, indicium.adapters.scitask, so that existing imports keep working.

    KGmemory (indicium.adapters.kgmemory)¶

    indicium.adapters.kgmemory ¶

    KGmemory-ready projection (latent). Points outward at mem:SemanticMemory.

    We do NOT import, vendor, or modify KGmemory's vocabulary — we only reference its canonical IRI so an emitted ASB Claim is ingestible if/when KGmemory adopts it. The ECO->validationState crosswalk is intentionally NOT here (it is KGmemory's seam to author).
